수학 진단 — 운영 절차서 (교사용)

전부 브라우저에서. 명령어·git 불필요. 이 페이지를 북마크해두세요.

매일 흐름 한눈에: ① 문항 관리에서 문제 등록 → ② 진단 페이지에서 학생 답안 업로드해 진단 → ③ 프로파일에서 학생별 누적 결과 확인.
세 화면(북마크용):
  • 문항 관리: admin_items.html
  • 학생 진단: index.html (제목: 수학 취약유형 진단)
  • 학생 프로파일: profile.html (제목: 학생 관측축 누적 프로파일)
★ 지금은 등록과 진단이 분리되어 있습니다. 등록한 문항은 D1에 쌓이기만 하고, 진단에 자동으로 반영되지는 않습니다(선택형 출제 연결은 다음 단계). 등록은 "문제 은행을 채우는 일"로 보시면 됩니다.

① 문항 등록 — 화면: 「문항 관리」(admin_items.html)

처음 1회 — 연결 설정

  1. 맨 위 연결 설정 칸에 Worker 주소 · 데이터 base URL · 쓰기키를 넣고 설정 저장.
  2. 연결 확인(/health) → D1=O · key=O 나오면 준비 완료. (이 설정은 브라우저에 저장돼 다음부터 생략)

문항 하나 등록

  1. 1) 단원 선택에서 단원 고르기.
  2. PDF에서 문항을 복사해 문항 원문 칸에 붙여넣기(본문+정답+해설 함께여도 됨) → AI 구조화 →.
  3. 2) 검수·수정에서 본문·정답·해설·유형을 확인·수정. (유형은 AI가 제안해 드롭다운에 선택돼 있음. 개념은 자동.)
  4. 미리보기로 확인 후 저장 →.

여러 문항 연속 등록 요령

  • 저장하면 폼이 자동으로 비워집니다 → 바로 다음 문항 원문을 붙여넣고 반복.
  • 중간에 폼을 비우고 싶으면 새 문항(폼 비우기).
  • 같은 단원 문항을 몰아서 하면 빠릅니다(단원 재선택 불필요).
유형을 못 정한 문항 = 보류(pending)로 저장됩니다. 나중에 3) 등록 목록에서 보류(pending)만 필터 → 해당 행의 유형지정 클릭 → 폼에 불러와짐 → 유형 골라 저장 → 하면 승인으로 승격됩니다. 목록 상단에 승인 / 보류 / 보관 건수가 항상 보이니, 보류가 쌓이면 정리해 주세요.

② 학생 진단 — 화면: 「수학 취약유형 진단」(index.html)

  1. 학생 이름 입력.
  2. 학생 코드: SC-STUDY- 뒤 숫자 3자리만 입력(예: 7 → SC-STUDY-007). 같은 학생은 항상 같은 코드여야 기록이 누적됩니다. 칸을 클릭하면 최근 코드가 뜹니다.
  3. 진단 자료 파일 올리기 — PDF · 이미지(사진) · txt 가능. 문제 번호와 풀이 흔적이 보이게.
  4. (선택) 고급 입력에 학생 풀이 텍스트를 넣으면 파일 없이도 됩니다.
  5. 1차 진단 시작 클릭 → 1~2분 후 결과. (필요 시에만 보강 문제 10문항 생성)
  6. 진단이 끝나면 📊 이 학생 … 이전 기록·축 누적 보기 → 링크로 프로파일로 바로 갈 수 있습니다.

③ 결과 확인 — 화면: 「학생 관측축 누적 프로파일」(profile.html)

  1. 학생 코드 조회에 3자리 넣고 조회.
  2. 축 합산 표: wrong(합)이 반복해서 높은 축 = 이 학생의 반복 취약축.
  3. 시험 목록 표: 날짜·범위·문항수·이 시험 축·관측 태그(원본)(= 학생 풀이에서 나온 원문 태그)까지 확인.
서버(D1) 누적을 쓰려면 profile 화면의 서버 저장(D1)·동기화에서 Worker 주소·RECORD_WRITE_KEY를 넣고 서버 설정 저장. 백업은 전체 내보내기 (JSON) / 가져오기 (JSON 파일).

④ 자주 나는 문제와 대처

화면이 옛날 그대로 (수정한 게 안 보임)

  • 주소 끝에 ?fresh=1을 붙여 여세요(숫자는 매번 바꿔서: ?fresh=2…). 예: …/admin_items.html?fresh=1
  • 배포 직후엔 최대 10분쯤 뒤 자동으로 새로 반영됩니다.

저장이 안 될 때

  • 문항 관리: 연결 확인(/health)이 D1=O · key=O인지. 쓰기키가 맞는지. 본문이 비어있지 않은지.
  • 붉은 실패 메시지에 이유가 나옵니다(키 불일치 / 바인딩 없음 등).

유형을 못 정한 문항

  • 그냥 저장하면 보류(pending)로 남습니다(버려지지 않음). 나중에 보류(pending)만 → 유형지정으로 승격.

학생 기록이 안 보임

  • 진단할 때 학생 코드가 매번 같은지 확인(오타=다른 학생). profile은 그 코드로 조회.
