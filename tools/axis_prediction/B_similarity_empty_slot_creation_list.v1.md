## 1. 창작이 들어간 곳은 없습니다 — 세 갈래 다 실측

### 1-1. PT 번호 — 슬롯 산술
```
slot n -> PT(3n-2)/PT(3n-1)/PT(3n)      인계문 §1-2
검증    87종 전량 재계산. pos = (PT-1) mod 3 / slot = ceil(PT/3)
        pos <-> 접미사 1:1  예외 0/87
          pos0 개념·조건 판별   24종
          pos1 비례식·정리 적용 39종
          pos2 복합 계산·증명   24종
        접미사 없는 엔트리 0/87
점유    53슬롯 / 87엔트리  (인계문 §1-2 와 일치)
충돌    PT016·PT092·PT108·PT137 은 카탈로그에 없음 (4/4 부재 확인)
```

### 1-2. base 이름 — 두 경로가 같은 문자열로 수렴
```
경로 ①  mathflat 순서 정렬  mf#9 / mf#35 / mf#40 / mf#50
경로 ②  학습지 인쇄 라벨    NEWLABEL 14건의 worksheet_label
대조    바이트 동일 4/4  (grep -Fx 완전일치. 육안 대조 아님)
```
★ 인계문 §1-3 표는 mf#40 을 `삼각형의 무게중심(2) △ABC, △GBC` 로 줄여 적었습니다.
원문은 `삼각형의 무게중심(2) △ABC, △GBC의 무게중심` 이고, 학습지 라벨과 여기까지 동일합니다.
**표기가 잘린 것이지 이름이 다른 것이 아닙니다.**

★ 인계문 §7 보류항이 지적한 "이름 순서 정렬 적중률 4/6 = 67%" 는 **이 4건에는 해당하지 않습니다.**
그 67% 는 순서 정렬 단독의 성적이고, 이 4건은 학습지 라벨이 같은 문자열을 독립으로 증언합니다.

### 1-3. pos — D1 이 실제로 배정한 PT 의 칸
문항이 요구하는 칸을 정할 때 쓸 수 있는 신호를 먼저 점검했습니다.

```
difficulty 로 도출  불가.  ①인계문 §1-2 가 GPT 전사분에 금지
                          ②실제로 14건 전부 core 라 판별력 0 (독립 확인)
본문 판독으로 도출  불가.  창작이 됩니다
D1 배정 PT 의 pos   사용.  엔진이 이 문항을 몇 번 칸으로 판정했는지의 관측치입니다
                          base 는 틀렸어도(빈 슬롯이라 갈 곳이 없었으므로)
                          칸 판정은 별개 신호입니다
```

```
슬롯  요구문항  배정 PT 의 pos                       혼재
 6      5건    0,0,0,0,0                            없음
31      2건    1,1                                  없음
36      4건    2,2,2,2                              없음
46      3건    1,1,1                                없음
```
★ **14건 전부 슬롯 안에서 칸이 일치합니다.** 칸 신호가 잡음이라면 섞여야 하는데 섞이지 않았습니다.
★ 그래도 이것은 **관측이지 정의가 아닙니다.** 검수가 다른 칸을 지정하면 그대로 따릅니다.

### 1-4. concept_ids — 슬롯번호 = 개념번호
```
규칙 검증  concept_ids == M2_SIMPY_C{slot:000}   불일치 0/87
교차 증인  문항은행이 참조하는 개념 = 53종
           결손 6개 = C001 C003 C006 C031 C036 C046
           = 빈 슬롯 6개(1·3·6·31·36·46) 와 정확히 일치. 예외 0
```
★ 이 대조는 카탈로그가 아니라 **문항은행**에서 나온 것이라 §1-1 과 독립입니다.
C006·C031·C036·C046 은 "없는 개념"이 아니라 **"점유되지 않은 개념"** 입니다.

## 4. ★판정 필요 4건 — 기계 도출이 안 되는 것들

여기부터는 실측으로 값이 정해지지 않습니다. 임의로 채우면 창작이라 비워 두고 올립니다.

```

       출처는 mathflat 순서정렬 + 학습지 인쇄 라벨(§1-2)입니다

       variant_bank 로 찍으면 그 취지가 깨집니다
```

### 4-2. `response_formats`
```
기존   87종이 전부 서로 다른 조합(30가지). 문항에서 귀납된 값입니다

       status 가 raw_registered_not_wired 이고 카탈로그 pending 에도 걸려 있습니다
```

### 4-3. `representation_types` — ★별건 결함 동반
```
제안   []  (빈 배열). 사유는 §4-2 와 같음
```
★ **그런데 이 필드가 기존 데이터에서 오염돼 있습니다.**
```
증상   representation_types 에 PowerShell 배열 속성명이 값으로 섞여 있음
       "Count","IsFixedSize","IsReadOnly","IsSynchronized","Length",
       "LongLength","Rank","SyncRoot"  ← 실제 값이 아님
실측   87종 중 66종(75.9%)에 혼입

                LongLength, Rank, similarity_geometry_diagram, SyncRoot]

       인계문 §6 "ConvertTo-Json 전량 재직렬화 금지" 와 같은 계열입니다
```
```
요청  이 트랙에서 고칠지 별도 트랙으로 뺄지 판정해 주십시오.
      ★생성 작업과 섞지 않는 편이 낫다고 봅니다. 66종 수정은 blast radius 가 다릅니다
      ★신규 4종은 어차피 [] 이므로 이 결함을 상속하지 않습니다
```
