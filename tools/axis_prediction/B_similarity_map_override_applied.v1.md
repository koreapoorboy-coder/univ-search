## 2. ★★ override 줄별 진단 — 한 줄이 의심스럽습니다

"숨어 있던 오배정이 드러났다"고 쓰기 전에, **override 가 틀렸을 가능성**을 먼저 쟀습니다.
각 override 라벨이 붙은 **배정 보유 문항**이 그 override 를 지지하는지 봤습니다.

```
라벨                                    mf  slot   OK  CELL  BASE  NOID   판정
평면도형에서 닮음의 성질                    3    2    3     0     0     6   ✔ 뒷받침
변의 길이에 따른 삼각형의 종류               69   56    5     0     0     6   ✔ 뒷받침
피타고라스 나무 문제                       76   58    4     2     0     6   ✔ 뒷받침
다면체에서 닮음비의 응용                     6    4    2     0   ★1     6   △ 대체로 뒷받침
★피타고라스 정리의 활용(3) 직사각형 내부의 점  73   57  ★0     0   ★4     6   ★전면 충돌
항상 닮은 도형                            2    2    0     0     0     2   - 미검증
각기둥에서의 최단 거리                      80   59    0     0     0     3   - 미검증
```

### 2-1. mf#73 은 0/4 입니다 — 철회를 제안합니다
```
그 라벨이 붙은 배정 보유 문항 4건이 ★전부 override 와 다른 슬롯을 가리킵니다
지지 0건. 반대 4건
```
```
정렬 근거   mf#73 -> slot 57, 유사도 0.375
            정렬은 ★유사도가 아니라 mathflat 순서 DP 로 병합합니다
            slot 57 에는 mf#72·73·74·75("활용(2)(3)(4)(5)")가 함께 묶여 있습니다
반대 근거   D1 은 4건 전부를 slot 53 "사각형·직사각형에서 피타고라스 정리" 로 배정했고,
            라벨에 "직사각형"이 들어 있어 slot 53 base 와 문자열이 겹칩니다
```
★ **어느 쪽이 옳은지 Code탭이 판정하지 않습니다.** 다만 0/4 는 "숨은 오배정 발견"보다
"override 오류"쪽 설명이 더 단순합니다.
```
제안  mf#73 행을 override 에서 ★빼고 다시 돌릴 것
효과  BASE 5 -> 1 · NEWLABEL 0 -> 4
      그 4건은 다시 NEWLABEL 로 돌아가 판정 대기 상태가 됩니다
★Code탭이 임의로 빼지 않았습니다. 판정해 주십시오
```
