# 제출16 — 전사본 batch_id 오프셋 규명 · 대응 5번째 독립 확인

발신 Code탭 · 수신 검수 · 2026-08-21
회신 대상: **검수 판정 18차 §0(좌표 확정) · §9(추가 사례 확인 요구)**

## 0. 결론 세 줄

```
검수의 §0 판독은 맞습니다. 다만 범위가 보유본 1건이 아니라 전사본 7건 전부입니다.
틀린 필드는 전사본의 bulk_batch_id 하나이고, provenance.source 는 처음부터 옳았습니다.
D1 은 무오염이고, 대응 simpy-M <-> setM 은 다섯 번째 독립 경로로 재확인됐습니다.
```

**정정 요청 1건**: 판정 18차 §0 은 "보유본 자체가 잘못된 배치ID를 달고 있었다"로 적었습니다.
사실은 **모든 전사본이** 그렇습니다. 보유본은 특이 사례가 아니라 **정상 사례**입니다.

## 1. 확정된 사슬

```
전사본 파일 simpy-N
   provenance.source = 260711_도형의 닮음(N).pdf
   파일명 규칙        (N) = set(N+1)
   내용 실측          set(N+1)                   <- 신규 도구, D1 미경유
   실제 투입처        D1 batch simpy-(N+1)       <- source_note 완전일치 150/150
=> D1 batch simpy-M  =  setM                      <- 기존 대응 그대로
```

**즉 전사본의 `bulk_batch_id` 만 1 낮습니다.** `provenance.source`·내용·D1 배치번호·세트번호
네 가지는 서로 정합합니다. 어긋나는 것은 파일 안의 배치ID 한 필드뿐입니다.

검수 보유본(`simpy-05` 라벨 · `닮음(5)` 출처 · set06 내용)은 **D1 simpy-06 으로 들어갔습니다.**
검수는 그 본문을 D1 **simpy-05** 배정과 맞췄으므로, 판정 8차 §2 는 실제로 서로 다른 학습지를
대조한 것이 맞습니다. **무효화 판정은 그대로 유지됩니다.**

## 2. 근거 ① — 내용 -> 세트 (D1 미경유)

신규 도구 `identify_transcript_to_set.ps1`.
문항별로 전사본의 `source_note + question_text` 를 건초더미로 삼고, **같은 question_no 에
학습지가 인쇄한 라벨**이 얼마나 되울리는지를 문자 바이그램 포함률로 재어 150문항 평균을 냅니다.

## 3. 근거 ② — 전사본 -> D1 (완전일치, 점수 아님)

`source_note` **문자열 완전일치**로 조인했습니다. 유사도 판단이 아닙니다.

```
전사본 simpy-0 (잘림)  ->  D1 simpy-03    150/150   (공백 정규화 후. 원본 2건은 연속공백 차이)
전사본 simpy-03        ->  D1 simpy-04    150/150
전사본 simpy-04        ->  D1 simpy-05    150/150
전사본 simpy-05        ->  D1 simpy-06    150/150   <- 검수 보유본
전사본 simpy-06        ->  D1 simpy-07    150/150
전사본 simpy-07        ->  D1 simpy-08    150/150
전사본 simpy-08        ->  D1 없음          0/105   <- set09 내용. 인계문 "set09 D1 미투입"과 정합
```

★ 공백 2건은 도구 diff 로 확인했습니다(연속공백 1개 차이). 육안 재입력본이 아닙니다.

## 8. 신규 도구

```
identify_transcript_to_set.ps1     전사본 내용 -> 세트 식별. D1 미경유
```
3종 시험 + 회귀:
```
① 정상 통과   7배치 채점, 행렬·판정 산출 (§2)
① 회귀        2회 실행 출력 SHA256 동일 EB628B56...C3639
② 실패        없는 경로 -> "input not found: ..." 로 명시적 중단
③ 오판별      구조가 다른 JSON(_inbox 태깅본) 투입
              -> "REFUSED: no batch produced usable items (input structure not recognised)"
③ 오판별      스키마가 다른 CSV(pairing) 를 -Headers 로 투입
              -> "REFUSED: headers csv has no column question_no (found: bulk_batch_id,set_declared)"
형식          191행 · 비ASCII 0바이트 · ASCII 자기검사 블록 보유
해석불가분    조용히 건너뛰지 않고 SKIP/WARN 행으로 출력 (문항등록표 폴더 = SKIP (no json))
```
