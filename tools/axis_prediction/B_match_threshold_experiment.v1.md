# 문항 매칭 임계값 실험 (정규화·유사도·숫자) (2026-08-10)

> 검수 요청: 99% 임계값 검토. 정규화 후 점수 상승·하한/상한 분포·안전 임계값 제안.
> 결론: **유사도 단일 임계값 불가**(숫자만 다른 동일유형 문항과 겹침). **정규화 + 숫자 시퀀스 정확일치 + 타입필터** 복합 규칙 필요.

## 방법
- 정규화: 위첨자→^n(²→^2), 공백 제거, ×·−류 기호 통일, 문장부호 제거, 소문자화.
- 유사도: 문자 bigram Dice.
- 숫자 시퀀스: 본문의 모든 숫자열 추출·순서비교.

## 해석
1. **정규화 효과 큼**: 표기만 다른 같은 문항 raw 0.66~0.71 → norm **1.000**. 정규화 필수.
2. **★상한 위험**: 숫자만 다른 문항(C) norm 0.76~0.85 = 같은문항 OCR오독(B1) 0.863과 **겹침**. → 유사도 θ 하나로 못 가름(θ=0.86이면 B 놓침, 0.84면 C 오매칭).
3. **숫자 시퀀스가 완벽 판별**: 같은문항 Y, 숫자만다름 N.

## 제안 매칭 규칙
`같은 problem_type_id(타입필터) AND 정규화 숫자시퀀스 정확일치(주판별) AND 정규화 유사도 ≥ 0.80(보조) AND 2위 마진 ≥ 0.05` → 아니면 미매칭(AI 폴백).
- 오매칭 0 수렴(숫자 다르면 무조건 미매칭). 미매칭률은 AI의 **숫자 오독률**에 좌우 → 사용자 실데이터로 실측(match_lab.html).

## 한계·후속
- 위 pair는 구성 모델. 표기·숫자 성분은 정확하나 **실 AI OCR 오독률(비숫자·숫자)**은 라이브 필요 → `match_lab.html`로 사용자 실데이터 대조.
- 재현 perl 스크립트: 아래.

```perl
# 정규화
sub norm { my $s=shift;
  $s=~s/²/^2/g; $s=~s/³/^3/g; $s=~s/¹/^1/g; $s=~s/⁴/^4/g; $s=~s/⁵/^5/g;
  $s=~s/×/*/g; $s=~s/·/*/g; $s=~s/−/-/g; $s=~s/–/-/g;
  $s=~s/[.,·、。]//g; $s=~s/\s+//g; return lc($s); }
# 문자 bigram Dice
sub dice { my($a,$b)=@_; my(%ca,%cb);
  my @A=split//,$a; for my $i (0..$#A-1){$ca{$A[$i].$A[$i+1]}++}
  my @B=split//,$b; for my $i (0..$#B-1){$cb{$B[$i].$B[$i+1]}++}
  my($na,$nb,$in)=(0,0,0); $na+=$_ for values%ca; $nb+=$_ for values%cb;
  for(keys%ca){my $m=$ca{$_};my $n=$cb{$_}//0;$in+=$m<$n?$m:$n} return $na+$nb?2*$in/($na+$nb):0; }
sub digits { my @d=(shift=~/(\d+)/g); return join(",",@d); }
```

## 확정 (2026-08-11): 임계값 0.99 — 텍스트 체제
- no-lexchange(어휘변경금지 전사강제) 배포 후 **10문항 재측정**: question_text 채움 10/10·유형매칭 10/10·같은문항 유사도 전부 **1.0000**·다른문항 최대 **0.9260**·마진 **7.4pp**·분포 미교차 → **임계값 0.99 확정**(사용자 최초 제안대로).
- ★위 모델pair의 "단일 θ 불가" 위험(숫자만다름 C norm 0.76~0.85 ↔ 같은문항 OCR오독 B1 0.863 **겹침**)은 **드리프트(요약·어휘변경) 전제**였다. 어휘금지로 같은문항이 1.0에 붙으면서 겹침구간이 붕괴 → 텍스트 입력 체제에선 단일 θ=0.99 성립.
- **숫자시퀀스 정확일치 복합규칙은 폐기 아님 — 이미지 체제 대비 예비**로 유지(드리프트 재등장 시 주판별로 복귀).
- ⚠ **이번 확정은 텍스트파일 입력 기준.** 실 학생답안=PDF·사진이라 판독 난이도 다름. **대량투입 전 PDF·이미지로 재측정(0.99 유지 확인) 게이트**. 미달 시 임계 하향이 아니라 (a)복합규칙 채택 or (b)이미지답안 매칭 제외.
- 후속 필드 결정: [[B_user_items_field_requirements.v1.md]] — similarity·숫자시퀀스·마진 전부 question_text 런타임 파생이라 어느 규칙을 채택해도 **저장 필드 불변**.

## PDF·이미지 실측 프로토콜 (2026-08-11, 대량투입 전 게이트)
목표: **이미지/PDF OCR에서도 같은문항이 0.99를 넘는지.** 텍스트파일은 글자를 그대로 읽지만 사진·스캔은 손글씨·그림·흐린 스캔이 섞여 판독 난이도가 다름. 여기서 미달이면 매칭 설계 재검토(수만 건 투입 후 알면 늦음).

★**충실도**: 실제 입력 = 학생 답안지(인쇄된 문제 + 손글씨 풀이 + 그림). 따라서 `file`은 **실제/대표 학생 답안지 사진**이 이상적(문제만 있는 깨끗한 PDF보다 현실적). 없으면 인쇄본을 사진 찍은 것.

**원본 텍스트(origs) 준비 — 사용자 부담 최소화, 보유 자료별:**
- **A. 시험지 디지털 원본(HWP/Word/텍스트PDF) 보유 → 타이핑 0.** 문항 텍스트 복붙 → origs. 같은 시험지 사진/스캔 → `file`. **순수 이미지-OCR 저하만 측정**(권장).
- **B. 텍스트레이어 PDF 보유** → PDF 텍스트 복붙 → origs. 같은 PDF(또는 인쇄 후 촬영) → `file`.
- **C. 스캔 이미지만 있고 디지털 원문 없음** → 대표 **10~15문항만 1회 타이핑**해 origs. ★이 타이핑은 버려지지 않음 = **어차피 등록할 question_text**(등록 미리보기). 억지로 전량 옮길 필요 없음.

**절차**: ocr_measure `?fresh=1` → Worker주소·base 저장 → 단원 선택 → `file`=답안지 사진/PDF → origs=원문(문항번호 순, 10~20건) → 실행.

**주의(페어링)**: 표의 AI question_text 열과 원본 열을 같이 봄. 낮은 행이 나오면 **먼저 그 행의 AI question_text가 같은 문항인지 확인**(그림·번호 오독으로 옆 문항과 짝지어진 페어링 착시일 수 있음) → 진짜 OCR 저하와 구분.

**판정(검수 확정)**:
- **≥0.99**: 그대로 진행(3~6 착수).
- **미달**: 임계 하향 아님(오매칭 위험 = 최후수단). 다른 대책 — (a)이미지 답안은 매칭 제외 / (b)유형·개념 필터로 좁히고 유사도는 보조(=이미지 체제 복합규칙). 저하 원인이 체계적(상첨자·그림캡션·손글씨 번짐)인지 무작위 노이즈인지에 따라 대책 갈림.
- ★미달 행 발생 시 Code탭이 **ocr_measure에 문자단위 diff 표시**를 추가 → 어디서·어떻게 어긋났는지 즉시 판별(체계적 vs 무작위). 통과하면 불요.

### ★측정 아티팩트 발견·수정 (2026-08-11)
PDF 실측 중 **worker `qtext-required`(구버전) run에서 min 0.0000 · ≥0.99 1/20**의 이상 결과 관찰. 원인 = **OCR 실패 아님, ocr_measure 페어링 버그**:
- AI가 진단 JSON에 **그룹 엔트리**(콤마 번호 `02, 03`·`04,15,16` 등 + 빈 question_text + AI 즉석생성 `QF_XXX` 유형명, 데이터에 없음)를 방출.
- 구 `collect()`가 이를 함께 긁고, **정렬-인덱스 페어링**이라 origs와 1칸씩 밀림 → 실추출은 정상인데 전부 오짝 → near-zero(가설 ② 실증).
- **수정**: ocr_measure `collect→번호매칭`으로 교체 — 단일 정수 question_no만 채택해 `origs[i]=i+1번`으로 매칭(추가 엔트리에 안 밀림) + 빈본문/그룹엔트리 제외 + **낮은 행(<0.99) 문자 diff 인라인 표시**. 합성목업 검증 통과(그룹엔트리 interleave에도 번호 정렬 유지).
- ⚠ 재측정은 **수정본 배포 후 + worker=`no-lexchange`**로. 헤더에 `번호매칭 20 · 그룹엔트리제외 N` 확인.
- 관측된 good run(min 0.9241·≥0.99 17/20)은 유형매칭 20(그룹엔트리 0)이라 페어링 정상 → **판정 유효**. 단 low 3행 diff는 수정본 재측정으로 확정.
- 별건 워치: 진단 attempts에 그룹엔트리가 섞이는지(원문 JSON 필요) → 프로덕션 매칭(5번) 시 attempts 필터 필요할 수 있음.
