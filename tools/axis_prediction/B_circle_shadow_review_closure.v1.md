# 원의 성질 Shadow 독립 검수 종결 보고 v1

작성: Codex · 2026-08-31
대상 단원: `M3_CIRCLE_PROPERTIES`
근거 검수: Claude 코드탭 검수본 + GPT/Claude `RECHECK33` 독립 판정 + Codex 최종 대조

## 1. 결론

- D1 추출본의 2,168개 `user_items.id`와 정적 Shadow 등록부의 2,168개 ID는 집합으로 일치한다.
- 기존 등록부에는 33문항에서 필수 참조형 축 34개가 빠져 있었다.
- 두 독립 검수본은 JSON·상태·등록값 계약을 모두 통과했다.
- 빠진 축 기준 33문항 중 24문항은 처음부터 일치했다.
- 처음 불일치로 집계된 9문항 중 6문항은 `O′`, `O2`, `large`처럼 로컬 참조 이름만 달랐고 수학 판정은 같았다.
- 실제 판정 대조가 필요했던 3문항은 Codex가 그림·문제·해설을 다시 읽어 종결했다.

## 2. 최종 판정 3건

### R003 — 원 O와 △CDG의 외접원

`교차`로 판정한다. 주어진 길이와 해설에서 계산한 중심·반지름을 적용하면 두 원은 C 외의 한 점에서도 만난다. 외접원이 원본 그림에 그려져 있지 않다는 이유만으로 `unjudgeable`로 두지 않는다.

### R013 — 원 O와 M·N·P·C의 공통 원

`교차`로 판정한다. P와 C가 두 원의 공통점이다. 기존 점 위치 중 M을 `outside`로 둔 값도 독립 판정과 그림에 따라 `inside`로 바로잡는다.

### R025 — 원형 구멍과 동전

기존 승인대로 관계축은 `unjudgeable`을 유지한다. 동전이 기울기 시작하는 임계 순간은 동일 평면의 정적 두 원 관계만으로 전부 표현되지 않기 때문이다. 다만 빠져 있던 두 원의 provenance와 풀이에 사용한 점-원 위치 참조는 보완한다.

`review_state='unjudged'`만 세어 완료라고 판정하던 방식은 폐기하고, 문항마다 필수 축 키 3개가 실제로 있는지 검사한다. coverage도 원본에서 복사하지 않고 등록부 생성 시 다시 계산한다.

## 4. 런타임 안전장치

- 활성 Shadow 명세 `item-axis-spec.v2`를 공개 데이터 경로에 둔다.
- manifest와 등록부 양쪽에 `diagnostic_authority:false`를 둔다.
- 엔진은 `student_output:false`, `profile_eligible:false`, `diagnostic_authority:false`, `remediation_enabled:false`가 모두 맞아야 등록부를 읽는다.
- 저장 경로도 같은 안전 조건을 만족한 Shadow 관측만 보존한다.
- D1 pending 문항 조회는 고정 `LIMIT 3000`을 제거하고 1,000건 단위 페이지 조회로 바꾼다.
- Shadow 대상 단원은 워커의 한 상수 집합에서 관리해 분기 중복을 줄인다.

## 5. D1·학생 화면 경계

- 이번 종결 작업은 D1을 쓰거나 기존 학생 데이터를 소급 변경하지 않는다.
- 학생 화면·학생 프로필·처방에는 Shadow 결과를 출력하지 않는다.
- 앞으로 학생 제출에 검증된 Shadow 문항이 포함되면 `axis_records`에 비출력 관측이 추가될 수 있다. 이것은 누락 레코드 보존이라는 승인된 동작 변화이며, 학생 진단값이나 처방 확정으로 쓰지 않는다.
