# ISSUE — `type_name_source` 값 정의 (등재)

신설 2026-08-21 · 근거: **검수 판정 20차 §4-1** · 도입 커밋 계보 `971056a9`(표식 도입)

---

## 왜 이 필드가 있는가

카탈로그의 `type_name` 이 **어디서 온 이름인지**를 구분하기 위해서다.
이름의 출처가 다르면 신뢰 근거도 다르고, 나중에 이름이 어긋났을 때 어느 쪽을 정본으로 볼지가 달라진다.
표식이 없으면 `variant_bank` 에서 온 이름과 학습지에서 읽은 이름이 구별되지 않는다.

---

## 값 정의

| 값 | 뜻 | 근거 |
|---|---|---|
| `variant_bank` | 조립 시점에 type_variant_bank(patch209) 에서 가져온 이름 | 인제스트 산출분 |
| `worksheet_label` | 학습지가 인쇄한 유형명이 그대로 base 이름이 된 것 | 학습지 라벨 + mathflat 순서정렬이 **같은 문자열로 수렴**한 경우에만 |

### `worksheet_label` 부여 조건 (전부 만족해야 함)
```
① 학습지 PDF 가 인쇄한 라벨을 그대로 base 로 쓴다.  변형·요약·창작 금지
② mathflat 해당 슬롯 leaf 이름과 바이트 동일할 것    (독립 경로 교차확증)
③ type_name = base + " - " + pos 고정 접미사        (접미사는 pos 에서 기계 도출)
```

### 현재 보유 현황 (2026-08-21)
```
variant_bank      87종   M2_SIMPY 기존 엔트리
worksheet_label    4종   M2_SIMPY_PT016 · PT092 · PT108 · PT137 (빈 슬롯 6·31·36·46)
```

---

## ★★ 이 표식은 출처 기록이 아니라 **맵 진입 조건**이다

판정 21차 §2 지시로 명문화한다.

```
잘못 이해   "이름이 어디서 왔는지 적어 두는 메타데이터"
실제        ★대조 도구가 이 값을 보고 라벨->슬롯 맵에 넣을지 말지를 정한다
결과        variant_bank 로 잘못 찍으면 그 유형은 영원히 NEWLABEL 로 남는다
            엔트리는 멀쩡히 있는데 대조가 그 존재를 모른다. 오류 메시지도 나지 않는다
```
★ **다음 단원에서 같은 상황(앞머리 세트에만 인쇄된 유형)이 오면 여기서 막힌다.**
빈 슬롯을 학습지 라벨로 채울 때는 반드시 `worksheet_label` 로 찍을 것.

---

## 부수 효과의 실제 — 왜 그렇게 되는가

`compare_pdf_label_to_assignment.ps1` 의 **라벨→슬롯 맵은 인제스트 문항은행(set04/set09)에서만** 만들어진다.
앞머리 세트에만 인쇄된 유형은 문항은행에 표본이 없어서, **카탈로그에 엔트리를 만들어도 영원히 NEWLABEL 로 남는다.**

`type_name_source = worksheet_label` 인 엔트리는 **base 이름이 곧 인쇄 라벨**이므로 스스로 맵에 들어갈 수 있다.
도구가 이 표식을 읽어 맵을 보충한다(판정 20차 이후 도입, 2026-08-21).

```
실측  라벨->슬롯  67 (문항은행) + 4 (worksheet_label 엔트리) = 71
      NEWLABEL   35 -> 21
```

★ 그러므로 이 값을 `variant_bank` 로 잘못 찍으면 **이름 표기만 틀리는 것이 아니라 대조가 동작하지 않는다.**

---

## ★형제 칸은 출처를 상속한다 (판정 24차 §4)

같은 base 의 다른 칸(pos)을 나중에 만들 때, 그 이름은 **base 에서 기계 도출**된 것이다.
학습지가 준 것도, variant_bank 가 준 것도 아니다. 그러면 무엇으로 찍는가.

```
규칙  ★해당 base 를 이미 가진 형제 엔트리의 type_name_source 를 그대로 상속한다
사유  같은 base 의 형제 칸이다. 이름의 출처가 같다
예    슬롯14 기존 PT040·PT042 가 variant_bank -> 신설 PT041 도 variant_bank
      슬롯47 기존 PT140 이 variant_bank      -> 신설 PT139·PT141 도 variant_bank
      슬롯6  기존 PT016 이 worksheet_label   -> 신설 PT017·PT018 도 worksheet_label
★     base 가 서로 다른 값을 가진 형제를 갖고 있으면 상속할 수 없다. 그때는 판정을 받을 것
      (현재 M2_SIMPY 에는 그런 슬롯이 없다 — 슬롯당 출처 1종)
```
적용 실적: 2026-08-21 형제 칸 8종 신설(PT041·068·071·079·139·141·150·164) 전부 `variant_bank` 상속.
