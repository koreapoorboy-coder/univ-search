## 0. ★제가 또 틀렸습니다 — "통계는 개념층까지 잘렸다"

제출10 §4·별건2에서 통계를 이렇게 규정했습니다.
```
✕ 통계만 개념층도 함께 잘렸다. 절단 깊이가 다르다
```
**틀렸습니다.** 통계의 개념층은 다른 두 단원과 **똑같이 온전**합니다.

```
M3_STAT  엔트리 23 · concept_ids 보유 23/23 · 길이 1개=23 · 슬롯번호=개념번호
M3_CIRC  엔트리 47 · concept_ids 보유 47/47 · 길이 1개=47 · 슬롯번호=개념번호
M2_SIMPY 엔트리 87 · concept_ids 보유 87/87 · 길이 1개=87 · 슬롯번호=개념번호
                                          ⇒ 구조 동일. 통계만 다르지 않다
```

실제로 다른 것은 **조립이 닿은 범위**입니다.
```
통계 PT번호 = 2, 5, 8, 11, ... , 65, 74   ← 전부 PT(3n-1), 즉 pos1 한 칸씩만
슬롯        = 1~22 그리고 25             ← 23·24 건너뜀, 26~36 미도달
```

| 단원 | 관측 슬롯 수 | **최대 슬롯** | 선언 base | 판정 |
|---|---|---|---|---|
| M2_SIMILARITY_PYTHAGORAS | 53 | **59** | 59 | 최대슬롯 = 선언 → 선언 뒷받침 |
| M3_CIRCLE_PROPERTIES | 31 | **42** | 42 | 최대슬롯 = 선언 → 선언 뒷받침 |
| M3_TRIGONOMETRIC_RATIO | 36 | **36** | 36 | 최대슬롯 = 선언 → 선언 뒷받침(대조군) |
| M3_STATISTICS | 23 | **25** | 36 | 최대슬롯 < 선언 → **뒤쪽 미관측** |

⇒ 통계는 **뒤쪽 11슬롯(26~36)에 문항이 하나도 없었을 뿐**입니다. 개념층이 잘린 것이 아닙니다.

## 1. ★그래서 개념 증인의 강도를 정확히 다시 적습니다

제출10에서 개념 max를 "정식 종수의 증인"이라고 썼는데, 정확히는 **하한의 증인**입니다.

```
개념 max = 조립이 도달한 최대 base 슬롯
        = 정식 base 수의 하한   (그 이상이라는 것만 말해준다)

닮음    C059 → base >= 59.  선언 59 와 일치 ⇒ 선언을 뒷받침
원의성질 C042 → base >= 42.  선언 42 와 일치 ⇒ 선언을 뒷받침
삼각비  C036 → base >= 36.  선언 36 와 일치 ⇒ 대조군
통계    C025 → base >= 25.  선언 36 → 미달. 반증도 입증도 아님
```

⇒ **닮음 177 판정은 그대로 유효합니다**(개념 증인이 59를 하한으로 주고, 선언 177 = 59×3 과 정합). 다만 개념 증인 단독으로 "59가 상한"임을 증명하지는 못합니다. 네 경로 중 상한을 고정하는 것은 **docs 선언과 manifest 회계**입니다.

★ 판정을 재론하는 것이 아니라, **증거가 무엇을 말하고 무엇을 말하지 않는지** 정확히 적어 두는 것입니다. 이 구분이 없으면 다음 단원(통계)에서 같은 논리를 잘못 적용합니다.

## 2. CHECK 7 수정 — 3분기로 갈랐습니다 (시험 ③이 또 잡음)

초판은 `개념 max × 3 == 선언`이 아니면 전부 FAIL이었습니다. 그래서 **통계에 허위 FAIL**을 냈습니다.

```
개념max×3 >  선언   FAIL   선언이 너무 작다. 실제 결함
개념max×3 == 선언   ok     조립이 마지막 슬롯까지 닿음. 선언 뒷받침
개념max×3 <  선언   under  뒤쪽 미관측. ★결함 아님. WARN 으로만 보고
```

실행 결과:
```
CHECK 7 concept/slot number bad : 0
  [WARN] M3_STATISTICS: concept max 25 x3 = 75 < declared 108 -
         tail slots never observed, declaration NOT witnessed (CHECK 7 under, not a defect)
CHECK 2~6 : 3 / 3 / 6 / 3 / 0   (초판과 동일 = 회귀 통과)
CHECK 8 : declared 13192 / actual 12788 / deficit 254 / unexplained 150 → DOES NOT CLOSE
```
★ 판정 13차 §2 지시대로 **원인이 밝혀진 150도 계속 뜨게 두었습니다.**

### 3종 시험
| 시험 | 입력 | 결과 |
|---|---|---|
| ① 정상 | 40단원 전수 | CHECK 2~6 불변(회귀) · CHECK 7 FAIL 0 · CHECK 8 remainder 150 |
| ② 실패 | 없는 `-Repo` | `data dir not found`, exit 1 |
| ③ 오판별 | **선언 초과 합성 픽스처**(개념 max 5 × 3 = 15 > 선언 6) | `EXCEEDS declared - the declaration is too small` **FAIL 정확히 검출** |
| ③ 오판별 | 통계(미관측) | FAIL → **under 로 격하**(이번 수정) |
| ③ 오판별 | 개념 번호 체계가 다른 3단원 | n/a + WARN(직전 수정) |
| ③ 오판별 | `-Unit` 지정 / manifest 선언 없음 | CHECK 8 미출력 / SKIPPED |

## 3. §5 경로 B — 도구를 먼저 만들었습니다

`tools/axis_prediction/match_d1_hints_to_base.ps1` (신설, ASCII 전용, 3종 시험 통과)

### 분류 규칙 — ★슬롯 거리가 아니라 계열로 가릅니다
검수 사례를 보고 기준을 고쳤습니다. **슬롯 21과 22는 인접하지만 계열이 다릅니다.** 슬롯 거리로 가르면 검수가 base 충돌이라 한 것을 칸 충돌로 잘못 분류합니다.
```
계열(family) = mathflat 중영역.  제출7 순서정렬 결과에서 추출
  닮은 도형 4 · 삼각형의 닮음 조건 9 · 평행선과 선분의 길이의 비 14 ·
  삼각형의 무게중심 16 · 넓이의 비 2 · 겉넓이의 비 2 · 부피의 비 2 ·
  닮음의 활용 1 · 피타고라스 정리 6 · 피타고라스 정리의 활용 3      = 59슬롯
파일 = tools/axis_prediction/B_simpy_slot_family.v1.csv
       (align_catalog_to_mathflat.ps1 -EmitSlotFamily 로 생성)
```
```
OK    유형후보 힌트에 가장 잘 맞는 base 가 배정된 base 다
CELL  같은 계열이고 점수 차가 작다 (인접 base 사이에서 갈림)      피해 제한적
BASE  계열이 다르거나 점수 차가 크다                              ★처방이 빗나감
HOLD  점수가 낮거나 차이가 미미해 판정 불가                        ★억지로 가르지 않음
NOID  problem_type_id 가 비어 있음
```
★ 점수는 **후보 추리기용**이지 판정이 아닙니다. BASE 행은 전부 **검수 판정 대상 후보**로만 냅니다. 도구는 데이터를 고치지 않습니다.

### 기지의 정답으로 시험 (검수 §5 사례 형태 재현)
```
q37  slot 21 -> 22   sim 0.037 -> 0.667  same-family   BASE
     assigned : 삼각형 외각의 이등분선과 넓이비
     best     : 여러 평행선 사이의 길이비
q62  slot 32 -> 12   sim 0.033 -> 0.650  DIFF-family   BASE
     assigned : 사각형 각 변의 중점을 이은 사각형
     best     : 직각삼각형 닮음의 길이·넓이 응용
```
검수가 base 충돌로 지목한 두 사례의 **형태를 재현**합니다.
⚠ 단 위 힌트는 실제 `source_note` 원문이 아니라 **제가 만든 시험용 문자열**입니다. 실데이터 대조는 파일 수령 후입니다. 시험용임을 명시해 둡니다.

### 3종 시험
| 시험 | 입력 | 결과 |
|---|---|---|
| ① 정상 | 합성 6행(OK 1 · BASE 3 · NOID 1 · 접두어없음 1) | 전부 의도대로 분류 |
| ② 실패 | 컬럼 누락 / 없는 파일 | `REFUSED: required column missing` · `input not found` |
| ③ 오판별 | **슬롯 스킴이 아닌 카탈로그**(mathflat 81종) | 초판이 **27슬롯으로 잘못 읽고 진행**했음 → `한 슬롯에 base 이름 2개` 가드 추가해 거부 |
| ③ 오판별 | slot 컬럼 없는 family 파일 | `REFUSED: slot-family file has no slot column` |

★ ③의 첫 항목을 기록합니다. **초판이 mathflat 카탈로그를 조용히 27슬롯으로 해석했습니다.** 슬롯 스킴을 전 단원에 가정했던 무결성 도구 초판과 **같은 실패**이고, 같은 시험이 세 번째로 잡았습니다.
