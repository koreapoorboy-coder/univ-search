## 1. 프로젝트 목적

학생이 틀린 문제를 보고 **"무엇을 못 해서 틀렸는지"** 를 알아내는 진단 엔진.

사용자는 수학을 직접 가르치지 않습니다. **데이터가 세밀해야 학생 지도에 명확한 답을 줄 수 있습니다.**

최종 목표는 **태그 세분화**입니다. 현재 321종은 PDF 문항을 보고 예상한 것이고, 학생 실제 풀이가 쌓이면 새 오류 유형을 발견해 더 정밀하게 만드는 것이 목표입니다.

**설계 원칙**: 사용자가 손을 대야만 돌아가는 구조. 판단은 사람이, 반복은 기계가. 판매 형태는 서비스형(데이터는 사용자 보유).

## 3. 현재 진행 중 — 문항 매칭 설계

### 배경
사용자가 문항을 대량 등록하고, 그 안에서 학생에게 출제할 계획입니다.
**학생 답안이 등록 문항을 찾아 매칭되어야** 유형 추측이 사라지고 정확도가 올라갑니다.

### 확정된 설계
```
1차: unit_id + problem_type_id 로 후보 축소
2차: 정규화 본문 유사도 ≥ 0.99
미달·모호 → 매칭 실패 → AI 추측 폴백
```

**임계값 0.99 확정** (직전 세션 마지막 판정)
```
같은 문항 (텍스트 파일)  1.0000
같은 문항 (실제 PDF)     0.9241 ~ 1.0000, 17/20이 ≥0.99
다른 문항 최대           0.9260
```
오매칭 위험 없음. 미매칭 15%는 허용(손실 없이 AI 추측으로 폴백).

### 원칙
- **문항 번호 매칭 배제** — 시험지를 재구성하면 번호가 흔들림
- **오매칭보다 미매칭이 낫다** — 틀린 해설이 붙으면 진단이 망가짐
- 후보가 여럿이면 매칭하지 말 것

## 4. 직전 세션 마지막 판정 (미처리)

PDF 실측에서 0.99 미달 3건의 원인을 diff로 확인했습니다.
**정규화 문제가 아니라 AI 판독 오류였습니다.**

```
문항 1 (0.9241)  k(k-2)x² → k(k-2)x^2   지수 표기 혼용
문항 4 (0.9873)  -(a + b) → -(a - b)     ★ 부호 오독
문항 15 (0.9784) 제1,2,3사분면 → 사면분   글자 순서 오류
```

**Code탭에 전달한 요청** (회신 대기 중):
1. 정규화에 `^2 ↔ ²` 통일이 있는지 재확인. 있다면 왜 문항 1에서 안 걸렸는지
2. 부호·글자 오독의 빈도. 다른 시험지에서도 나타나는지
3. **진단 경로에도 같은 오독이 있는지** — 매칭보다 이것이 더 중요할 수 있음
4. 다음 단계 착수: 스키마 v3 → JSON 스펙 → GPT 명세서 → 매칭 구현

## 7. 실무 함정 (반드시 숙지)

### 파일 전달
- Code탭에 첨부해도 **디스크에 실재하지 않을 수 있음**(간헐적)
- 확실한 방법: 사용자가 파일 탐색기로 직접 저장
  ```
  C:\Users\user\projects\scshstudy\tools\axis_prediction\_inbox\
  ```
- 정본 리포는 `C:\Users\user\projects\scshstudy` (OneDrive 사본 아님)

### 캐시 (가장 자주 발생)
- `/health` 확인 시 **`?t=숫자`** 를 붙일 것. 안 붙이면 옛 응답이 뜸
- 정적 파일 변경 후 **`?fresh=N`** 으로 페이지를 열 것
- **HTML 자체가 캐시되면** `?v=` 갱신도 무력화됨
- 사용자가 `Ctrl+Shift+R` 해도 안 되는 경우가 있음

### 버전 문자열
- 검수가 추정해서 안내하지 말 것. **Code탭이 정확한 문자열을 명시**하게 할 것
- 실제로 `work-capture`로 안내했으나 실제는 `fixA-work-text-preserve`였던 사고 발생

### SQL
- 검수가 스키마를 추정해서 만들지 말 것
- **Code탭에 파일 원문을 그대로 받아** 사용자에게 전달할 것
- `CREATE TABLE IF NOT EXISTS`는 잘못된 기존 테이블을 안 고침 → `DROP` 필요 여부 명시

### PowerShell
- 한글 리터럴이 ANSI로 깨짐. 스크립트는 ASCII로, 한글은 별도 UTF-8 JSON으로 분리

### push 누락
- Code탭이 커밋만 하고 push를 안 해 사이트에 반영 안 된 사고 2회
- 사용자가 열어야 할 파일은 **`public/` 아래**에 두고 push까지 확인
