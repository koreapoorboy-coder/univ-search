## 4. ★★슬롯 6 — SSS라는 추론에 반대합니다 (증거 3갈래)

검수 추론: *"SSS·SAS·AA는 교과서 고정 3종이다. 슬롯 7=SAS, 8=AA이므로 6=SSS."*
형태는 옳지만, **이 플랫폼의 택소노미에는 SSS 전용 자리가 없습니다.**

**증거 ①** — mathflat(독립 원본, 81군)도 **SAS·AA만 별도 군**이고 SSS 군이 없습니다.
```
mf#8  삼각형의 닮음 조건                    <- 슬롯 5
mf#9  두 삼각형이 닮음이기 위하여 필요한 조건  <- 슬롯 6 자리
mf#10 삼각형의 닮음 조건의 응용(1) SAS 닮음   <- 슬롯 7 (SAS)
mf#11 삼각형의 닮음 조건의 응용(2) AA 닮음    <- 슬롯 8 (AA)
```
SSS는 mf#8의 topic_types 안(`주어진 삼각형의 닮음 조건` 등 4개)에 흡수돼 있습니다. **"SAS·AA만 응용 군을 갖는다"는 비대칭이 두 목록에서 독립적으로 재현**됩니다.

**증거 ②(가장 강함)** — ★**SSS는 이미 슬롯 5에 들어가 있습니다.** 우리가 저작한 처방이 그렇게 적혀 있습니다.
```
M2_SIMPY_PT013  (= 슬롯 5, pos 0)  삼각형의 닮음 조건 판별 - 개념·조건 판별
  problem_nature : "주어진 조건이 SSS·SAS·AA 중 어느 닮음 조건에 해당하는지 판별하는 유형"
  student_command: "…주어진 변·각의 개수를 세고, 각이 두 변 사이에 있는지 확인한 뒤
                    SSS·SAS·AA 중 하나를 이름까지 써서 답하라."
  (data/display/problem_type_instruction_map_parts/…part04.v1.json)
```
즉 **SSS 판별 과제는 슬롯 5가 이미 담당**하고 있고, 이는 실제 문항을 보고 저작한 결과입니다. 슬롯 6을 SSS로 만들면 슬롯 5와 과제가 겹칩니다. mathflat이 mf#8 안에 SSS를 흡수한 것과 **같은 처리**입니다.

> ⚠ **자기정정**: 이 절의 초안에 "닮음 데이터 전체에 SSS 언급 0건"이라고 썼다가 폐기했습니다. 실제로는 위 처방 2건(PT013·PT015)에 있습니다. `grep`의 나머지 히트가 전부 도형의 성질(합동)과 `CROSSSET`(CROSS+SET) 오탐이어서 **부재로 단정할 뻔했습니다.** 부재 주장 대신 실재 증거를 확인한 결과, 결론은 같으나 근거가 훨씬 강해졌습니다.

**증거 ③** — 슬롯 7·8의 이름 변환 규칙이 mf#10·11과 정확히 대응합니다.
```
mf#10 …의 응용(1) SAS 닮음  →  슬롯 7 SAS 닮음의 조건 적용
mf#11 …의 응용(2) AA 닮음   →  슬롯 8 AA 닮음의 조건 적용
```
같은 규칙을 mf#9에 적용하면 슬롯 6 = `두 삼각형이 닮음이 되기 위한 필요 조건` 계열이 됩니다.

⇒ **판정 요청**: 슬롯 6을 (a) mathflat 정렬안 `두 삼각형이 닮음이 되기 위한 필요 조건`으로 할지, (b) 교과서 3종 대칭을 살려 `SSS 닮음의 조건 적용`으로 창작할지. **Code탭 권고 = (a)** — (b)는 두 원본 어디에도 근거가 없고, 실제 문항이 SSS 유형을 요구하면 D안 절차상 그때 만들면 됩니다.
