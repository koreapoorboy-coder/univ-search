# 유형 예측표 (predicted_axes) — 규칙 + 생성 스크립트

45단원 분류표의 각 유형에 대해 「여기서 잘 틀리는 축」을 규칙으로 예측한다.
분류표(어디에 속하는가)와 별개이며, **predicted_ 전용** — 학생 실측(observed_)과
절대 같은 필드에 저장하지 않는다.

### 패치 반영 방식 (파일 전송 실패 시)
검수 채팅→Code 탭 파일 전송이 불안정할 때(zip 3회 중 2회 유실), 규칙 블록을 **채팅 본문에
JSON 텍스트로** 받아 반영한다. 절차: v(n) 을 복사→`domain` 끝에 블록 텍스트 삽입→`version` 만 상향.
**재직렬화 금지**(ConvertTo-Json 은 한글 escape·키순서·공백을 바꿔 기존 팩의 바이트동일성을 깬다) —
텍스트 삽입으로 기존 팩을 바이트 보존하고, 삽입 후 common+각 팩을 v(n)과 대조 검증한다.
정규식 `\\(` 는 JSON 문자열에서 `\(` 가 되므로 두 백슬래시 그대로 둔다.
- **기존 팩 수정이 필요한 경우(v9 CA2_M2D)**: 바이트동일 불변식을 그 팩만 완화한다 —
  `applies_to`·`note` 등 지정된 필드만 문자열 치환(치환 매치 수=1 확인), 나머지 팩은 완전 동일,
  수정 팩도 `rules` 배열은 바이트 동일. 다른 단원(예: M2D)의 실행 결과 불변을 재실행으로 확인.

### PF 코드 충돌 처리 (v4 호출 규약)
`PF` 는 소인수분해(M1S1)·다항식곱셈(M3S1) 두 단원에 붙는다. 팩은 prefix 로 선택되므로
호출 키를 **`PF_M1S1` / `PF_M3S1`** 로 갈라야 팩이 안 섞인다(Python 은 CLI 인자, 포팅은
`unit_code=PF → PF_$학기` 매핑). 규칙 `applies_to` 도 `["PF_M1S1"]`. 나머지 44단원은 prefix 유일.

### v4 변경 (누적)
- `유형요약` 시트 → 배지없음 묶음을 묶음 이름으로 1행 방출(45단원 156건).
- **`pack_gap` 시트**: 걸렸으나 단원팩(D-) 못 짚고 공통(C-)만 걸린 항목 = 팩 필요성 실제 지표.

## 실행 (Python + openpyxl) — 정본

```bash
python build_axis_prediction.py <분류표.xlsx> <PREFIX> [출력.xlsx]
```

`axis_rules.v20.json` 은 스크립트와 같은 폴더에 둔다. 출력 시트: `predicted_axes`
· `unmatched` · `pack_gap` · `warnings` · `rule_freq` · `meta`.
PF 두 단원은 prefix 를 `PF_M1S1` / `PF_M3S1` 로 넘긴다(위 「PF 코드 충돌 처리」).

## 정본 / 역할 (안 A + 분업)

- **예측표 공식 생성**: Python 스크립트(검수 채팅). 이 리포지토리의 정본이다.
- **저장·git·결과관리 + 45단원 대량 실행**: Code 탭.
- 이 환경(Code 탭)에는 python3 가 없다. `tools/mathflat_builder/Run-AxisPrediction.ps1`
  이 **v4 를 저장 JSON 에 포팅한 대량 실행기**다 — xlsx 를 매번 검수 채팅에 올리는 것이
  비현실적이라, 45단원 전량은 여기서 돌리고 검수 채팅은 표본으로 교차검증한다.
  두 구현은 **AELF 에서 총353·적중96%·팩76%·gap20%·이름단독92%·요약전용1 로 완전 일치**
  (v2 `detect_layout` 의 단원단위 층선택 버그도 이 교차검증이 잡았다).

  ```powershell
  # 45단원 전량 (또는 -Only M2D 로 한 단원)
  tools\mathflat_builder\Run-AxisPrediction.ps1
  ```

  출력 CSV(임시폴더\axispred): `name_source_dist` · `unmatched_all` · `pack_gap_all` · `rule_over60`.
  `unmatched_all`·`pack_gap_all` 에는 **학기 열**이 있어 PF 코드 충돌(M1S1 소인수분해 /
  M3S1 다항식곱셈)을 분리한다.

## depth 는 행 속성이다 (중요)

한 단원 안에서 행마다 이름 출처가 섞인다 — 예: AELF 353행 중 세부유형 79 · 주제유형
273 · 유형묶음 1. 따라서 `depth` 를 **단원 단위 필드로 굳히지 말 것.**
`index.v1.json` 45단원 교체 시 이 점을 반영한다(단원 하나가 group_only 인 경우는
GEC 처럼 전 행이 유형묶음일 때뿐이다).
