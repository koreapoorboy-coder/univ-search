# GPT 문항등록 명세 v2 (2026-08-14 — (d) 유형 미배정 · 3단 구조)

> ★이 v2가 현행. v1(B_gpt_item_registration_spec.v1.md)은 (d) 이전 초안(카탈로그 §2·GPT 유형배정)으로 **폐기**. 같은 파일명 덮어쓰기 혼동 방지로 버전 분리(검수 2026-08-14).

> 역할: GPT가 시험지/학습지 PDF를 읽어 **[[B_bulk_injection_json_spec.v2.md]] §2 형식의 JSON**을 생성한다.
> ★**유형 배정 = 3단 구조(검수 2026-08-14)**: 1단 GPT(본문 전사 + 유형후보 힌트) → 2단 검수(카탈로그 기계 대조 → 확정/보류) → 3단 사용자(보류분만 판단).
> ★**GPT는 `problem_type_id`를 정하지 않는다.** 대형 카탈로그(중등도 87~448종·domain 필드 없음, [[B_catalog_layer_audit.v1.md]])에서 GPT 배정은 오배정→오매칭→틀린 처방 위험. GPT는 **정확 전사 + 유형후보 자연어 힌트**만.
> ★투입 후 소급 불가. 정확성 최우선 — 못 하면 비우고 표기하되 **틀리게 채우지 말 것.**

## 0. 대원칙 3
1. **원문 그대로.** 요약·어휘변경·재작성 금지(§2).
2. **모르면 비우고 표기.** 유형은 GPT가 안 정함 — `source_note`에 **유형후보 힌트**만(§4). 그림정보 없으면 명시(§3). 조용한 누락·창작 금지.
3. **스펙 준수.** 넣지 말라는 필드(`problem_type_id`·concept_ids·id·해시) 넣지 말 것(§6).

## 1. 산출 형식
[[B_bulk_injection_json_spec.v2.md]] §2 그대로. **단 항목에 `problem_type_id`를 넣지 않는다.** 한 배치 = 한 단원.
```json
{ "batch": { "unit_id":"M2_GEOMETRY_PROPERTIES", "org_id":"SCSTUDY", "bulk_batch_id":"SCSTUDY-2026-08-14-geom-01",
    "engine_data_base":"https://.../math-weakness-engine",
    "provenance": { "ingest":"bulk", "extraction":"gpt-<model>-pdf-202608", "source":"<학습지명>", "at":"<ISO>" } },
  "items": [ { "question_no":"1", "unit_id":"M2_GEOMETRY_PROPERTIES",
    "question_text":"<원문 그대로·그림정보 보완>", "answer":"", "explanation":"", "difficulty":"core",
    "source_note":"유형후보: 외심의 등거리 성질로 각 구하기" } ] }
```
→ `problem_type_id` 없음 → 서버가 전건 `pending` 저장 → 2단 검수 대조 → 3단 승격.

## 2. 전사 정확도 (원문 그대로 · 어휘변경 금지)
- **question_text·answer·explanation은 원문을 글자 그대로.** 요약·바꿔쓰기 금지(no-lexchange 취지). 매칭이 정규화 유사도 0.99로 도는데, 어휘가 바뀌면 같은 문항이 안 붙는다.
- ★**실제 오독 사례(ISSUE_ai_ocr_misread) — 이런 걸 내지 마라**:
  - 부호 오독: `-(a + b)`를 `-(a - b)`로 (문항4, 0.9873). **부호 하나가 다른 문항이 됨.**
  - 글자 전치: `제1,2,3사분면`을 `사면분`으로 (문항15). **글자 순서를 지켜라.**
- 수식은 **평문 표기**(LaTeX·백슬래시 금지): `1/3`, `루트2`, `x^2`, `<=`, `(123-1)/99`.
- 원문에 없는 정답·해설은 만들지 말 것 → `answer`/`explanation` 빈 문자열.

## 3. 그림 의존 문항 (★매칭 정확도 직결)
- 도형·그래프 문항은 **그림에만 있는 기호·수치가 본문에 안 들어오면 매칭 불가**.
- ★**그림에만 있는 정보를 question_text에 포함**: 점·선분·각의 이름, 그림 안 수치(변 길이·각도·좌표), "다음 그림에서"가 가리키는 대상.
- ★**보완 불가능하면**(원본이 그림에만 표기, 실제 사례 19번 △BFH 점H 본문 미정의) → 지어내지 말고 `source_note`에 `그림의존: <무엇이 본문에 없는지>` 명시.

## 4. ★ 유형후보 힌트 (source_note "유형후보:") — 2단 검수 대조의 입력
- GPT는 `problem_type_id`를 **정하지 않는다.** 대신 **문항을 읽은 판단을 자연어 힌트로 남긴다.** 검수가 이 힌트를 카탈로그와 기계 대조해 유형을 확정한다(2단). **힌트가 부실하면 2단 대조가 불가능** → 아래 형식을 지켜라.
- **형식**: `유형후보: <문항이 무엇을 묻는가> + <어느 개념·성질인가>`. 카탈로그 type_name을 추측해 흉내내지 말고, **문항 내용을 구체적으로** 기술.
- **예시(3+)**:
  - `유형후보: 삼각형 외심의 등거리 성질을 이용해 밑각 크기 구하기`
  - `유형후보: 평행사변형에서 두 대각선이 서로를 이등분함을 이용한 변의 길이`
  - `유형후보: 원주각과 중심각의 관계(중심각=2×원주각)로 각도 계산`
  - `유형후보: 이차함수 y=a(x-p)^2+q의 꼭짓점 좌표 읽기`
- **애매하면 애매하다고**: `유형후보: (불확실) 닮음비 관련으로 보이나 그림 정보 부족`. 억지 단정 금지.

## 5. 필드별 작성 규칙 (스펙 v2 §3 요약)
| 필드 | 규칙 |
|---|---|
| `question_no` | ✅ 필수. PDF 문항 번호 그대로(추적·pending 후처리·2단 대조 키). |
| `unit_id` | ✅ 배치 단원(섞이면 항목 override). |
| `question_text` | ✅ 원문 그대로·평문수식·그림정보 보완(§2·§3). |
| `difficulty` | `basic`\|`core`\|`advanced`\|`high` 중 하나(기본 `core`). ★이 4값만. |
| `source_text` | 있으면 넣고, 없으면 **넣지 마라**(서버가 복사 안 함). |
| `answer`·`explanation` | 원문에 있으면 그대로, 없으면 `""`. |
| `source_note` | ★**접두어 고정**: `유형후보: …`(§4, 사실상 필수) / `그림의존: …`(§3) / `메모: …`. 여러 개면 ` | `로 구분. 자유 텍스트 금지. |
| ~~`problem_type_id`~~ | ★**넣지 마라**(§6). GPT가 정하지 않음. |

## 6. 넣지 말 것 (서버가 처리/거부)
- ★`problem_type_id` — **넣지 마라**(3단 구조: 검수·사용자가 배정). 빈 문자열도 넣지 말고 필드 자체를 생략.
- `concept_ids` — 넣지 마라(런타임 조인).
- `id`·`content_hash`·`dedup_key`·`dedup_key_norm_version`·`org_id`·`bulk_batch_id`(항목레벨)·`provenance`(항목레벨) — 서버 생성/각인.
- LaTeX·마크다운·HTML 태그, 유형·정답·그림정보 창작.

## 7. ★ 자가검산 체크리스트 (출력 전 GPT가 스스로 확인 — 하나라도 아니오면 고쳐서 출력)
1. [ ] 모든 항목에 `question_no`·`unit_id`·`question_text` 있는가.
2. [ ] ★`problem_type_id`를 **넣지 않았는가**. 대신 `source_note`에 `유형후보:`를 §4 형식으로 적었는가(문항 내용+개념).
3. [ ] `question_text`가 **원문 그대로**인가(요약·어휘변경 0). 부호·글자순서 재확인했는가(§2 오독사례).
4. [ ] 그림의존 문항은 그림 정보를 본문에 넣었거나, 불가 시 `source_note`에 `그림의존:` 표기했는가.
5. [ ] `difficulty`가 4값(`basic/core/advanced/high`) 중 하나인가.
6. [ ] `source_text`를 question_text로 복사하지 않았는가(없으면 생략).
7. [ ] 금지 필드(`problem_type_id`·`concept_ids`·`id`·해시류·항목레벨 provenance/org_id)를 넣지 않았는가.
8. [ ] 수식이 평문(LaTeX·백슬래시 0)인가.
9. [ ] JSON이 유효한가(스펙 v2 §2 구조·batch+items).
10. [ ] 한 배치 = 한 단원 원칙을 지켰는가.

## 8. 산출 후 흐름 = 3단 유형 배정 (참고)
```
1단 GPT     이 명세대로 JSON 생성(본문 전사 + source_note "유형후보:"). problem_type_id 없음.
2단 검수     GPT JSON + 단원 카탈로그(problem_type_id·type_name 축약본) 기계 대조:
             유형후보 ↔ 카탈로그 type_name 매칭 → 확정 목록 [{question_no, problem_type_id}] / 애매하면 보류.
3단 사용자   검수가 보류한 소수 건만 판단. 확정 목록은 파일 업로드로 일괄 반영(spec v2 §6).
```
→ 투입 시 **전건 pending**이 정상. 유형은 2·3단에서 붙는다. GPT는 **정확 전사와 좋은 유형후보 힌트**에 집중하면 된다(억지 배정 0). ★유형후보가 정확할수록 2단이 자동 확정하는 비율이 높아져 3단(사람) 부담이 준다.
