## 1. §3-① 게이트 3항 개정

```
전  ① q1 시작  ② 결번 0  ③ ★추출 수 == -ExpectCount (고정 상수)
후  ① q1 시작  ② 결번 0  ③ ★규모 = 문항수/페이지수 가 밴드 안인가
    -ExpectCount 는 남겨 두되 ★선택 사항입니다(0 이면 검사 안 함)
```

### 1-1. ★밴드는 추정하지 않고 실측으로 잡았습니다
```
검수 제시  "대략 4문항/쪽"
실측       원의 성질 16개  1.67 ~ 2.24
           닮음     12개  2.14 ~ 2.27
           전체 28개      ★1.67 ~ 2.27
```
★ **검수 추정치가 약 2배 큽니다.** 4로 밴드를 잡았으면 **28개 전부 FAIL** 했을 것입니다.
그대로 쓰지 않고 재봤습니다.
```
채택 기본값  MinPerPage 1.2  ·  MaxPerPage 3.5
            (실측 최저 1.67 아래로 여유 · 최고 2.27 위로 여유)
            둘 다 파라미터라 필요하면 조일 수 있습니다
```

### 1-2. ★규모 게이트가 실제로 무엇을 잡는가 — 절단 시험
```
시험  260711_원의 성질.pdf 를 -MaxPage 20 으로 인위 절단
결과  80 items / 71 pages = 1.13  ->  [GATE-FAIL] scale ... outside 1.2..3.5
```
★ **이때 ①②는 통과합니다.** 잘린 결과가 q1~q80 연속이라 "완전한 런"으로 보입니다.
**절단을 잡은 것은 규모 게이트 하나뿐입니다.** 고정 상수를 뺀 자리를 이것이 메웁니다.

### 1-3. 3종 시험
```
① 회귀   16개 원의 성질 산출이 구 산출(ExpectCount 사용분)과 ★바이트 동일 16/16
② 실패   -MinPerPage 5 -> "[GATE-FAIL] scale: ... 2.11 per page, outside 5..3.5"
③ 절단   -MaxPage 20 -> 위 §1-2. ①②를 통과하는 입력을 ③이 잡음
```

### 1-4. 도구 손댄 김에 개명 (판정 26차 §6 방침)
```
extract_pdf_type_headers.ps1 의 한 글자 변수 5개 개명
  $i -> $lineIdx · $j -> $scanIdx · $k -> $segIdx · $n -> $qnum · $p -> $pageIdx
검증  한 글자 변수 0 · 대소문자 충돌 0 · 비ASCII 0
      ★회귀에서 산출 바이트 동일이므로 개명이 동작을 바꾸지 않았습니다
```
