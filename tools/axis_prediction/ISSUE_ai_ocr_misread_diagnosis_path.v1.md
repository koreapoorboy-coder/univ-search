# ISSUE: AI OCR 오독(부호·글자) — 진단 경로 영향 (별건, 2026-08-11)

> 발견 경로: PDF 실측(SC-STUDY 08/11, 20문항) low-3행 diff. 매칭 임계값(0.99)·필드결정과 독립. OPEN.

## 발견
정규화로 **못 고치는 실제 AI 오독** 확인(전사 강제·어휘금지에도 남음 = 요약이 아니라 지각오류):
- **문항 4** (0.9873): 원본 `-(a + b)` → AI `-(a - b)`. **부호 오독(+→-)**. 문제 내용 자체가 달라짐.
- **문항 15** (0.9784): 원본 `제1, 2, 3사분면` → AI `제1,2,3사면분`. **글자 전치(분면→면분)**.
- **문항 1** (0.9241): 검수는 "지수 혼용(`^2`/`²`)"으로 보고했으나 **정규화가 `^2↔²`를 흡수**함(NFKC `²→2` + `^`제거, 실측 dice 1.0). → 0.9241의 실원인은 지수 아님, **미확정**(별개 misread 추정). 원문 JSON의 실제 question_text 또는 도구 코드포인트줄 필요.

## 왜 중요 (매칭보다 상위 리스크 가능)
- **매칭엔 무해**: 오독 문항은 유사도 미달→미매칭→AI 추측 폴백. 오매칭 아님(안전 방향).
- **진단 경로엔 유해 가능**: 같은 엔진이 시험지/학생답안을 읽어 `response_status`·`observed_error_tags`를 판정. 부호·글자를 오독하면 **학생이 무엇을 틀렸는지 오판** 가능. 이건 매칭 정확도보다 상위 문제.

## 제약
- worker 이미 **effort=high** (상향 여지 작음).
- question_text 전사는 이미 **verbatim 강제**(요약 아님) → misread는 지각오류라 프롬프트만으로 줄이기 어려움.
