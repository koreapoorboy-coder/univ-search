## 1. [코드확인] — 목록 API 실태 (worker `math_diagnosis_worker.js:383-403`)
| 항목 | 실제 |
|---|---|
| 파라미터 | `unit_id` · `status` · `bulk_batch_id` · `limit` |
| `limit` | POST만 지원. 기본 **200**, 상한 **1000**(`Math.min(1000, …)`). GET은 limit 미지원(200 고정) |
| **`offset`** | ★**없음**. `ORDER BY created_at DESC LIMIT n` 뿐 |
| 반환 | `items` · `count`(반환수) · `total` · `counts`(status별) — ★counts/total은 **필터와 무관한 전역 집계** |
| `bulk_batch_id` 필터 | ★**이미 구현되어 있었음**(서버·클라 양쪽) |

**⇒ 판정: 이번 개선에 서버 변경 불요.** offset이 없어도 상한 1000건 이내에서는 클라 슬라이싱으로 요건을 모두 충족.

### ★함께 발견한 결함 (요청 외)
개선 전 클라는 `limit:500` 고정에 **잘림 표시가 없었음** → 등록이 500건을 넘는 순간 오래된 문항이 **조용히 사라짐**(사용자는 전건을 본다고 착각). 이번에 상한을 1000으로 올리고 **잘림 경고를 명시**했습니다.

### ★서버 페이지네이션이 필요해지는 시점 = 총 1000건 초과
현재 332~467건. "단원별 150문항 학습지 다수" 계획대로면 곧 초과합니다. 초과 시 화면에 빨간 경고가 뜨며, 그때 `offset` 추가(워커 변경 → VERSION 갱신 → 재배포)가 필요합니다. **지금은 하지 않았습니다**(요청 범위=정적 파일, 그리고 워커는 paste-deploy라 미배포 변경을 리포에 남기면 다음 배포에 섞여 들어감). 승인하시면 별건으로 준비하겠습니다.

## 4. 검증 [실측] — 로컬 정적 서버 + 가짜 데이터 120건으로 실제 구동

- 정렬: 숫자 `#2 …`, 문자 `#100 …` — ★검수 지적(`'100'`이 `'11'`보다 앞) 재현 및 숫자 옵션으로 해소 확인.
