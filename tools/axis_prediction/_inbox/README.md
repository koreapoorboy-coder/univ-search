# _inbox — 검수/GPT 산출물 수신함 (파일 전달 경로 표준)

## 문제 (2026-08 기록)
`@"C:\Users\...\Downloads\file.json"`로 채팅 첨부하면 Code탭 Read 도구는 **내용**은 읽지만
그 파일이 Code탭 디스크에 **실재하지 않아** `cp`·PowerShell·검증이 실패한다.
→ 두 번 "재수록"(내용 verbatim 재작성)으로 우회. GPT 산출물도 같은 함정.

## 표준 경로 (재수록 불필요)
1. 검수/GPT가 파일을 만든다 (Downloads든 어디든).
2. **그 파일을 이 폴더(`tools/axis_prediction/_inbox/`)에 저장**한다.
   - OneDrive 동기화 폴더라 Code탭 디스크에서 즉시 보인다.
3. Code탭에 **파일명만** 알려준다. (첨부 불필요)
4. Code탭이 디스크에서 직접 읽어 검증·처리하고, 최종 산출물은 `tools/axis_prediction/`에 배치한다.
5. 처리 끝난 원본은 이 폴더에 남기거나 커밋 시 정리.

## 왜 이게 되나
Code탭의 모든 파일 작업(cp·ConvertFrom-Json·git add)은 **리포 디스크** 대상이면 100% 동작.
리포 밖(Downloads 첨부)만 안 닿는다. 그래서 "리포 안에 두기"가 유일하게 확실한 경로.

## 대안 (급할 때)
- 채팅에 **내용을 텍스트로 붙여넣기** → Code탭이 리포에 write. (첨부 파일 링크보다 확실)
- 첨부(@경로)는 최후수단 — 되지만 매번 재수록 비용.
