## 1. ★문항이 원본 유형명을 달고 있다 — §4 "재료 부적합" 정정

| 항목 | 실측 |

⇒ 인계문 §4의 "재료 부적합" 판정을 **철회**합니다(문서 반영 완료). 이 트랙에서 우리가 틀린 일곱 번째이며, 형태는 또 같습니다 — **비교 축을 확인하기 전에 결론을 냈습니다.**

## 2. ★★빈 슬롯 6개 — 독립 증거가 제출7과 일치

300문항의 라벨을 mathflat 81군에 대응시키면 **라벨이 하나도 없는 군이 15개**입니다.
```
없는 mf# = 1, 2, 3, 5, 6, 9, 18, 35, 40, 50, 69, 73, 76, 79, 80
```
이 15개를 제출7의 순서정렬 결과에 비추면 정확히 두 갈래로 갈립니다.

| 갈래 | mf# | 정렬상 배정 슬롯 | 의미 |
|---|---|---|---|
| **빈 슬롯에 떨어짐** | **1 · 5 · 9 · 35 · 40 · 50** | **1 · 3 · 6 · 31 · 36 · 46** | ★**빈 슬롯 6개와 완전 일치** |
| 점유 슬롯에 떨어짐 | 2·3(→2) 6(→4) 18(→15) 69(→56) 73(→57) 76(→58) 79·80(→59) | 이미 다른 문항이 있는 슬롯 | 병합 슬롯의 부(副) 라벨 |

⇒ **빈 슬롯은 "이름을 잃어버린 자리"가 아니라 "이 두 학습지에 문항이 없었던 자리"입니다.**
⇒ 제출7(이름 순서 정렬)과 제출8(문항 라벨 부재)은 **서로 독립된 방법**인데 6개 슬롯에서 같은 답을 냈습니다.

### 이것이 검수 §1을 더 강하게 만듭니다
검수: *"자리를 비우려면 그 자리에 무엇이 와야 하는지 알아야 한다."*
실측된 기제는 이렇습니다.
```
인제스트는 mathflat 81군 -> 59 base 슬롯의 매핑을 갖고 있었다
학습지 300문항이 커버한 것은 그중 53슬롯분
문항이 없는 6슬롯은 번호만 남기고 건너뛰었다  <- 검수가 목록에서 읽어낸 흔적
```
**177은 정의 수**라는 판정이 문항 데이터로 재확인됩니다.

### 슬롯 6 = SSS 아님 (제출7 §4 재확인)
mf#9 `두 삼각형이 닮음이기 위하여 필요한 조건`이 빈 슬롯 6에 떨어집니다. SSS는 슬롯 5의 처방(`M2_SIMPY_PT013`)이 이미 담당합니다. **권고 유지 = mathflat 정렬안.**

## 3. ★★★접미사 — 3번 실패한 문제가 풀렸습니다. 예측이 아니라 조회입니다

검수 요구 ①("condition_count 같은 인코딩이 있는지 확인")의 답: **있습니다. 다만 condition_count가 아니라 `difficulty`입니다.**

### 닮음 — 문항 300건
```
difficulty   ->  pos  ->  접미사                 건수     예외
basic        ->   0   ->  개념·조건 판별          53       0
core         ->   1   ->  비례식·정리 적용       155       0
advanced     ->   2   ->  복합 계산·증명          92       0
                                          합 300 / 예외 0
```
`condition_count`(3/4/5/6)는 pos와 거의 무관했습니다(예: cc=3 → pos0 19 · pos1 30 · pos2 32). `observed_challenge_band`(정답률)도 약했습니다 — **원의 성질 시도1(정답률 밴드)이 실패한 이유가 여기서 재현됩니다.**

### 검수 요구 ②③ — 200/100 분할 검증
| 검증 | 결과 |
|---|---|
| 200 학습 / 100 검증 (item_id 정렬 후 3번째마다 검증분) | **100 / 100 = 100%** |
| 교차 세트 (set04 150으로 규칙 → set09 150 검증) | **150 / 150 = 100%** |
| 다수결 베이스라인 | 51.7% |
| 학습분 순도 | core 103/103 · basic 38/38 · advanced 59/59 |

**적중률 90% 기준을 통과합니다.**

### ★단, 이것을 "예측 성능"으로 읽지 마십시오 (교란 통제 보고)
`difficulty`와 `primary_problem_type_id`는 **같은 인제스트가 같은 시점에 함께 기록한 필드**입니다. 따라서 100%는 *독립 예측기의 성능*이 아니라 **두 필드가 같은 스킴의 두 표현임을 확인한 것**입니다(§7 "검증 기준은 검증 대상과 독립일 것"에 걸리는 구조).
⇒ 그러나 D안이 필요로 하는 것은 예측기가 아니라 **배치 규칙**이고, 그 목적에는 이것으로 충분합니다. 검수 표현대로 **"접미사는 판정 대상이 아니라 조회 대상"**이었고, 조회 키가 `difficulty`였습니다.

### 원의 성질 — 카탈로그 47종 (보류 트랙이지만 같은 키가 통합니다)

★**시도 4를 하지 않아도 됩니다.** 추정이 아니라 카탈로그에 이미 적혀 있는 값입니다.
⇒ 인계문 §6의 블로커(접미사 판정 3회 실패)가 해소됩니다. **원의 성질 편입 재개 여부는 검수 판정 사항**이라 착수하지 않았습니다.

## 4. 🔴 병합 슬롯 — D안 적용 전에 판정이 필요합니다

`source_type_label`이 서로 다른데 같은 슬롯에 들어간 경우를 셌습니다.

| 지표 | 실측(300문항 기준) |
|---|---|
| 2개 이상 라벨을 받은 슬롯 | **9개** (28·50·51·53·55·56·57·58·59) |
| 그 슬롯에 속한 문항 | **91 / 300 = 30.3%** |
| 2개 이상 라벨을 받은 PT 칸 | **14 / 87**, 문항 **83 / 300 = 27.7%** |
| distinct 라벨 67 vs base 슬롯 59 | 라벨당 1슬롯은 **구조적으로 불가**(8종 초과) |

검수 9차의 **405/1,200 = 34%** 와 같은 계열의 수치입니다(우리 표본은 리포에 있는 300건).

### ★그런데 병합된 슬롯의 이름이 병합 내용을 명시적으로 담고 있습니다
```
PT165  피타고라스 정리의 여러 증명            <- 유클리드 · 피타고라스 · 가필드 · 바스카라 4종
PT174  히포크라테스·피타고라스 나무·종이접기   <- 히포크라테스 · 종이접기
PT175  입체도형과 원기둥 최단거리             <- 입체도형 · 원기둥
PT157~9 사각형·직사각형에서 피타고라스 정리    <- 사각형(1)(2) · 직사각형의 대각선
PT148~9 닮음의 실생활 활용 - 높이·축척         <- 높이의 측정 · 축도와 축척
PT166~7 피타고라스 정리의 역과 삼각형 분류     <- 직각삼각형이 되기 위한 조건 · 각의 크기에 따른 분류
```
"여러", "·"로 나열, "…과 …" — **9개 병합 슬롯 전부가 자기가 흡수한 내용을 이름에 적고 있습니다.** 우연한 충돌이 아니라 **의도된 굵기 조정**으로 보입니다.

### 판정 요청 (D안의 범위)
```
D안 3단계 "필요한 칸이 비어 있으면 그때 엔트리 1개 생성"이 적용되는 대상은
  (a) 점유 슬롯의 결손 접미사 칸 72개      <- 슬롯 안이라 177 안에서 해결됨
  (b) 빈 슬롯 6개 x 3칸 = 18개              <- 177 안에서 해결됨
  (c) 병합 슬롯을 라벨 단위로 쪼개는 것      <- ★177 밖으로 나감(59 base로는 자리가 없음)
```
**(a)(b)는 177 안에서 닫히고, (c)는 닫히지 않습니다.** (c)를 하려면 59 base 자체를 늘려야 하고, 그러면 "177 = 정의 수"라는 §1 판정과 충돌합니다.

⇒ **Code탭 권고**: (a)(b)만 D안으로 진행하고, **(c)는 하지 않는다.** 근거 = 병합 슬롯 이름이 흡수 내용을 명시하므로 그 문항들은 이름상 갈 곳이 있고, 부족한 것은 **칸(접미사)**이지 **자리(base)**가 아닙니다. 다만 이 판단은 **검수의 405 수치가 base 충돌을 뜻하는지, 칸 충돌을 뜻하는지**에 달려 있어 확인이 필요합니다. 우리 표본에서는 칸 충돌 83건(27.7%)과 base 충돌 91건(30.3%)이 거의 겹칩니다.

## 5. 부수 발견 — 라벨에 줄바꿈이 박힌 문항 3건

슬롯 25에서 같은 라벨이 2종으로 갈려 보였는데, 실제로는 문자열 안에 **줄바꿈이 들어간 것**이었습니다.
```
정상   사다리꼴에서 평행선과 두 대각선의 길이(1) 평행선이 대각선의 교점을 지나지 않을 때
오염   …지나지 않을[LF]때        ← 문자열 안에 U+000A
대상   M2_SIMPY_150_S09_Q049 · Q050 · Q051  (3건, 문자열 길이 47, 제어문자 코드 10)
```
★콘솔 줄바꿈으로 착시일 수 있어 **코드포인트로 확인**했습니다(§7 "육안 재입력본 금지"). 3건 전부 실제 U+000A입니다.
공백 정규화 전 10슬롯 → 정규화 후 9슬롯. ★**본 문서의 모든 라벨 집계는 공백 정규화 후 값**입니다. 정규화하지 않았으면 병합 슬롯을 1개 과대계상할 뻔했습니다.
